    Class WorkerPool

    Maintains a pool of worker processes that each run an MCP server, and replaces them when needed.

    Workers are needed because SPARQL queries can not always be cancelled from within the process that runs them:

    • Queries that block the event loop make any timeout inside that worker unable to fire in the first place. Such workers stop sending MESSAGE_HEARTBEAT messages, upon which they are killed and replaced.
    • Queries that did time out keep consuming CPU and memory in the background, as Comunica offers no way to abort an ongoing query. Workers therefore ask to be replaced via MESSAGE_RECYCLE after a timeout, which lets them finish their pending responses while a fresh worker takes over.
